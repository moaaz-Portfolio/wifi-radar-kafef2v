# بنية WiFi Radar ذات الشريحتين دون راوتر

## التوصيل الشبكي

- TX node: ESP32-S3 في وضع SoftAP، ينشئ شبكة WiFi-Radar-Net بكلمة المرور 12345678.
- RX node: ESP32-S3 في وضع Station، يتصل تلقائيًا بالشبكة نفسها.
- Laptop: يتصل بالشبكة نفسها من خارج الغرفة ويشغّل Python Factory أو User Edition.
- عنوان SoftAP الافتراضي 192.168.4.1، وقناع الشبكة /24.
- البث الدوري من TX إلى 192.168.4.255:3333، UDP، حمولة 4 بايت.
- بث CSI من RX إلى 192.168.4.255:5005.
- بيانات حساس الباب تستمر على UDP/5006.

لا يلزم وجود راوتر منزلي أو إنترنت. الإنترنت مطلوب فقط لتنزيل الحزم أو تحديثات GitHub.

## إعداد RF

القناة المستخدمة افتراضيًا 1 (2412 MHz) وعرض HT20. معدل TX مضبوط على WIFI_PHY_RATE_MCS0_SGI (7.2 Mbps على HT20). حد قدرة الإرسال يضبط باستخدام القيمة 44 في API، أي 11 dBm بوحدات ربع dBm.

لم يتم فرض اليابان أو القناة 14. القناة 14 مخصصة لليابان 802.11b/DSSS، لذلك تتعارض مع HT MCS0-SGI. يجب الالتزام بتعليمات NTRA المصرية والقياس الفعلي لقدرة EIRP بعد حساب كسب الهوائي.

## معالجة CSI

1. يلتقط RX CSI من إطارات TX AP فقط بمقارنة MAC المصدر مع BSSID الذي أعاده esp_wifi_sta_get_ap_info.
2. ترفض الإطارات التي لا يبلغ CSI فيها 128 بايت أو يكون RSSI فيها أقل من/يساوي -75 dBm.
3. يحسب DSP مقدار الإشارة وطورها من أزواج imaginary/real.
4. تطبق نافذة Null/Guard mask على المؤشرات 0..5 و32 و59..63.
5. يحسب log amplitude ratio بين كل حامل والحامل المجاور، ثم فرق الطور المطوي إلى [-pi, pi]. تمزج الميزتان بنسبة 0.65 و0.35.
6. تجمع أول 300 إطار لتكوين baseline لكل حامل. أثناء هذه المرحلة يرسل byte 128 للحامل الصالح، و0 للحامل المحجوب.
7. بعد اكتمال baseline يطرح baseline، ثم يطبق EMA بمعامل 0.15 وdeadband بمقدار 0.015.
8. ترمز قيمة DSP الصفرية إلى byte 128، والقيم الموجبة/السالبة إلى مجال byte حول 128. هذا يحافظ على بروتوكول CSI1 الذي يتوقعه athena.

نسبة تراجع التداخل ليست ثابتة أو مضمونة؛ يجب قياسها مقابل خط أساس تجريبي.

## تشغيل وحدة Python

على اللابتوب بعد الاتصال بالشبكة:

    cd athena
    python -m pip install -r requirements.txt
    python -m athena --edition factory --host 0.0.0.0

للتسجيل والتدريب استخدم Factory Edition. بعد تدريب النموذج ومراجعة metrics مستقلة، شغّل User Edition:

    python -m athena --edition user --host 0.0.0.0

عنوان لوحة الويب على اللابتوب هو http://127.0.0.1:8000. إذا احتاج جهاز آخر الوصول، استخدم عنوان IP للابتوب على شبكة WiFi-Radar-Net والمنفذ 8000، مع إبقاء الجدار الناري مقيدًا بالشبكة المحلية.

## التحقق قبل جمع البيانات

1. شغّل TX وانتظر ظهور WiFi-Radar-Net.
2. اتصل من اللابتوب بالشبكة.
3. شغّل RX وانتظر رسالة الاتصال وعنوان IP وBSSID.
4. شغّل Python وتأكد أن عداد CSI/FPS يزيد وأن فقد الحزم معقول.
5. اترك الغرفة فارغة أول 3 ثوانٍ بعد تشغيل RX حتى ينتهي baseline التلقائي.
6. نفّذ معايرة الغرفة الفارغة في User Edition قبل المراقبة.
7. سجل بيانات متعددة عبر أشخاص وغرف وجلسات مستقلة.

## حدود الاختبار

- 100Hz تردد جدولة مستهدف، وليس ضمانًا لزمن إرسال ثابت أو Zero Jitter عبر Wi-Fi.
- قيمة 11 dBm لا تضمن حصر الموجة داخل الغرفة؛ التغطية تعتمد على الهوائي والجدران واتجاه اللوحتين.
- اختيار قناة محددة لا يعزل RF من كل شبكات الجيران؛ BSSID filtering يعزل مصدر بيانات CSI، لكنه لا يزيل التداخل الفيزيائي على القناة.
- فرق الطور قد يتأثر بأخطاء التردد والتزامن وتغيرات الأجهزة؛ لا يثبت التنفس وحده.
- يجب قياس false alarms وmisses وFPS وpacket loss في أكثر من غرفة وشخص قبل أي استنتاج علمي.
